## New stock failure and separate correction

The instruction-boundary variation changes one byte between a five-byte MOV
and five one-byte NOPs; both streams are valid. Its first stock x87 test exited
5 with no final oracle or exception report. Nine exact retries and sixteen
separately built reporting runs passed; that does not explain or erase it.

The reporting copy later captured c0000005 / execute access (8) at 0x25000024,
inside its own integer loop, while rewriting an IDENTICAL byte. There was no
x87 helper. The paired sequence stopped after four idle passes and this
failure; its remaining 43 planned cases did not run. This is a different
failure from found_x86_offset and is not proven to explain the first exit 5.

Wine's invalidation workaround removes/restores EXECUTE in separately locked
NtProtectVirtualMemory calls. Source review shows virtual_handle_fault can
see the intermediate non-executable metadata. Candidate
`build/wine-atomic-self/virtual.c` holds the existing recursive virtual_mutex
and signal mask across the local query/toggle/restore sequence. It is limited
to process == NtCurrentProcess(); remote APC pairs and explicit handles to
the current process are not corrected by this experiment.

The separately built candidate ntdll SHA is
1d7422cf6ce0c1223edcae6ec59a88300e29cd6ed2d1022eee3770170345ff4e.
Its runtime clone differs from the frozen baseline only in that Unix module.
All 48 reporting combinations pass (stock, unchanged upstream decoder-off/on;
four modes, integer/x87, first/prewarmed, sixteen batches). All sixteen existing
PE32/PE64 invalidation/mixed-region/owned-child/thread regressions also pass.
Both genuine PAGE_NOACCESS reporter controls fault and terminate as expected.
This supports the separate self-write race correction, not a game launch fix.
